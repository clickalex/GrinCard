Example profiles

Six fixture people, each with post-style link cards and wired to the four ways one URL can behave. Open any scenario below and watch the same profile show a different set of links — that is the whole idea of the project.

Your cards How it works
These are demonstrations, not enforcement.

In this static version the tier decision runs in your browser, and the private URLs are in the JSON your browser just fetched — so a determined visitor could read them. It proves the UX and the data model; the server-side version in ARCHITECTURE.md enforces it with the same resolveAccess(). Never put a genuinely secret URL in a static profile.

What the four scenarios mean

Stranger
Scans the printed card. Public links only — up to 5 on the free tier.
Temporary link
Got ?t=temp_… from the owner. Public links plus the one private link that token unlocks, until it expires or its use-count runs out.
Expired token
The same URL, later. It degrades to public — never a 404, never a leak.
Approved follower
Signed in and approved by the owner. Every link, including private ones.

Fixture data lives in examples/*.json and is read by the test suite too, so what you see here is what the tests assert. Copy one of these files into profile-data/, rename it, and run npm run build to start from a working example.

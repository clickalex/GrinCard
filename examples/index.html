Six fixture people, each themed with a different card template, each with one link to share. Copy it or open the card — the address is permanent, and the JSON behind it is what changes.

Your cards How it works
These are demonstrations, not enforcement.

A private link is hidden by the page, not by a server: on a static deployment the decision runs in your browser, and the private URLs are in the JSON your browser just fetched — so a determined visitor could read them. It proves the UX and the data model; the server-side version in ARCHITECTURE.md enforces it with the same resolveAccess(). Never put a genuinely secret URL in a static profile.

What each demo shows

One theme per profile.
Midnight — rahul123
Deep navy gradient, warm accent, Pinterest grid. The default look, and the one the printed card matches.

Blush gradient, centred serif name, pill-shaped cards. The centered layout on a light background.

Terra — sana-eats
Clay and cream, serif name, postcard trim size. Suits a kitchen or a studio.

Up to 5 links are public on the free tier. A link marked "visibility": "followers_only" stays off the page until the owner sends a link carrying a token for it — the same permanent URL, one extra link, and it degrades back to public once the token expires rather than showing a 404.

Fixture data lives in examples/*.json and is read by the test suite too, so what you see here is what the tests assert. Copy one of these files into profile-data/, rename it, and run npm run build to start from a working example.

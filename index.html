Make this yours in three steps

No build step, no account, no server.
  1. Rename the starter profile. profile-data/yourname.json → profile-data/<your-username>.json, and change "username" inside to match the filename exactly. That username becomes your printed URL.
  2. Edit your links in that one JSON file. Or use the dashboard to edit them with a form and see the tiers behave. Public links show to anyone; "private" ones only appear for a temporary token or an approved follower.
  3. Generate your link and print it. npm run build writes /c/<your-username>/ — the permanent URL that goes on the card. It appears below with a copy button and a QR code. Then open Print for a press-ready sheet.

Deploying to GitHub Pages? SETUP.md walks through enabling it, and .github/workflows/pages.yml regenerates your links on every push so you never have to.

How the tiers behave

Same URL, different visitor.

Anyone with the card

Scans the printed QR → sees public links only. Up to 5 on the free tier.

Someone you sent a temporary link

Opens ?t=temp_… → public links plus the one private link that token unlocks, until it expires.

An approved follower

Signed in and approved → every link, including private ones.

Everyone else

Expired token, revoked follower, or no session → back to public only. Never a dead end.

Want to see it rather than read it? Open the example profiles — they ship with live, expired and follower scenarios wired up. In this static version the tier decision runs in the visitor's browser, so it demonstrates the behaviour without enforcing it; ARCHITECTURE.md describes the server-side version, which uses the same resolveAccess().

This is your own deployment of QR Link Card, free and open source under MIT. Your profiles are JSON files in your repository; nothing is sent anywhere.
